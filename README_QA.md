# AIPS 사전진단 시스템 QA 가이드

AI 통합인허가 사전진단 서비스(`http://aips.iptime.org:17000`)의 **판정**과 **근거법령**이 정답셋과 얼마나 맞는지 자동으로 측정하는 도구입니다.

## 빠른 시작 (처음 받은 사람용)

**1. 설치 (최초 1회)** — Python 3.10 이상
```
cd nipa_ai_eval
pip install -r requirements.txt
```

**2. 화면 실행**
```
streamlit run qa_app.py
```
브라우저가 자동으로 열립니다. 다른 PC에서는 `http://<실행한 PC의 사내망 IP>:8501`로 접속합니다(`ipconfig`의 이더넷/Wi-Fi IPv4, 방화벽 8501 허용 필요). 종료는 터미널에서 `Ctrl + C`.

**3. 화면 주소**
| 주소 | 화면 | 용도 | 설명 |
|---|---|---|---|
| `/` | 규격서 시험 (AI 1 ~ AI 7) | 성능시험(TTA) 시험원용 기본 화면 | 9장, 12장 |
| `/dashboard` | QA 대시보드 (정답셋 기반 정확도·F1·일관성) | 내부 개발 점검 | 3~7장 |
| `/check` | 판단 여부 점검 (허가 가능·불가로 판단 못한 질의 찾기) | 내부 점검 | 10장 |

**4. 폴더**
| 위치 | 내용 |
|---|---|
| `*.py`, `.streamlit/` | 코드와 실행 설정 (공유 대상) |
| `gold.xlsx` | QA 대시보드 정답셋 |
| `spec_data/` | 규격서 시험셋·정답셋 (AI1~AI7) — 작성 규칙은 9-2 |
| `dashboard/`, `spec/`, `check/`, `run.log`, `run_status.json` | 실행 결과·상태 (각자 PC에서 생성되므로 공유하지 않아도 됨) |

**5. 알아 둘 것**
- 시스템 API 주소는 ⚙️ 설정에서 바꿉니다 (기본 `http://aips.iptime.org:17000/api`).
- 한 번에 하나만 실행됩니다. 질의 1건에 약 30~100초 걸립니다.
- 시스템 응답에 없는 값(버전 3종, 단계 로그, 룰셋 ID)과 AI6·7 연결 전 확인 사항은 9-7, 12-1에 정리되어 있습니다.

## 0. 테스트 항목 구분

| 항목 | 내용 | 도구 | 결과 파일 |
|---|---|---|---|
| **[AI 1]** 판정·근거 정확도 | 질의 1회 결과를 정답셋과 비교 (판정 정확도, 오허가·오불허율, 핵심근거 적중률, 조문 F1) | qa_runner.py → qa_eval.py | dashboard/pred.xlsx, qa_result.xlsx |
| **[AI 2]** 사전 진단 판단 F1 스코어 | [AI 1]과 같은 질문셋·정답셋·결과로 4종 판단 유형별 TP/FP/FN/TN, Precision·Recall·Specificity·F1, 가중평균 F1, 목표 달성 판정 | qa_f1.py | dashboard/f1_result.xlsx |
| **[AI 3]** 판단 일관성 | ① 동일 질의 N회 반복 ② 변형 질의(같은 의도·다른 표현) 시 판정·근거가 동일한지 | qa_runner.py --repeat N / --variants | dashboard/consistency/<시각>_반복·_변형/ |

## 1. 폴더 구성

```
nipa_ai_eval/
├─ gold.xlsx           정답셋 (사람이 작성)
├─ qa_app.py           화면(웹) — QA 대시보드 / 규격서 시험
├─ qa_runner.py        ① 시스템에 일괄 질의 → raw 저장 → pred.xlsx 생성 (두 기능 공통 호출 코드 포함)
├─ qa_eval.py          ② 정답셋(gold) vs AI 결과(pred) 채점 → qa_result.xlsx
├─ qa_f1.py            ④ [AI 2] 4종 판단 유형별 혼동행렬·F1 → f1_result.xlsx
├─ spec_*.py, spec_data/   규격서 시험 (9장)
├─ run_status.json · run.log · run_stop.flag   실행 상태 (두 기능 공통, 한 번에 하나만 실행)
│
├─ dashboard/          ◀ QA 대시보드 결과는 모두 여기
│  ├─ raw/             [정확도] 시스템 응답 원문 (케이스별 JSON)
│  ├─ pred.xlsx        [정확도] raw에서 판정·근거만 뽑은 표 (채점용)
│  ├─ qa_result.xlsx   [정확도] 채점 결과
│  ├─ f1_result.xlsx   [AI 2] F1 결과 (명령어 실행 시)
│  └─ consistency/     [일관성] 반복·변형 실행 결과 (실행 시각별 폴더)
│     └─ 20261020_1430_변형/
│        ├─ raw/                     {case_id}_{회차}.json
│        ├─ pred_repeat.xlsx         전 회차 추출 결과
│        └─ consistency_report.xlsx  일관성 리포트
│
├─ spec/               ◀ 규격서 시험 결과는 모두 여기 (spec/AIn/<시각>/)
│
├─ verdict_check.py, check_page.py, check_data/   판단 여부 점검 (10장)
└─ check/              ◀ 판단 여부 점검 결과 (check/<시각>/)
```

예전 버전에서 폴더 맨 위에 있던 `raw/`, `pred.xlsx`, `qa_result.xlsx`, `f1_result.xlsx`, `consistency/`는 화면이나 qa_runner.py를 처음 실행할 때 `dashboard/`로 자동으로 옮겨집니다(엑셀로 열려 있으면 그 파일만 건너뜀).

정확도 측정(1회 실행)과 일관성 측정(N회 반복)은 **저장 위치를 분리**해서 서로 덮어쓰거나 섞이지 않게 합니다.

## 2. 전체 흐름

```
gold.xlsx ──(주소+시설물)──▶ qa_runner.py ──POST 질의──▶ AIPS 시스템
                                   │◀──────── SSE 스트림 응답 ────────┘
                                   ├─▶ dashboard/raw/{case_id}_{회차}.json   (응답 원문 전체)
                                   └─▶ dashboard/pred.xlsx        (판정·근거 추출)
gold.xlsx + dashboard/pred.xlsx ──▶ qa_eval.py ──▶ dashboard/qa_result.xlsx           (요약 / 혼동행렬 / 케이스별)
```

## 3. 실행 방법

### 준비 (최초 1회)

```
pip install pandas openpyxl requests
```

시스템(`aips.iptime.org:17000`)에 접속되는 PC에서 실행해야 합니다.

### 기본 실행

```
cd C:\Users\user\Desktop\nipa_ai_eval
python qa_runner.py gold.xlsx --header 1     # 질의 + raw 저장 + pred.xlsx 생성
python qa_eval.py gold.xlsx dashboard/pred.xlsx   # 채점 → dashboard/qa_result.xlsx
```

- 질의 1건에 약 40~80초가 걸립니다. 콘솔에는 1건이 끝날 때마다 한 줄씩 출력됩니다.
- pred.xlsx는 1건마다 중간 저장되므로, `Ctrl + C`로 멈춰도 그때까지의 결과가 남습니다. 실행 중에는 pred.xlsx를 엑셀로 열어 두지 마세요(저장 실패).

### qa_runner.py 옵션

| 옵션 | 설명 | 예시 |
|---|---|---|
| `--header N` | 헤더가 있는 행 번호 (0부터). 첫 줄이 제목이면 `1` | `--header 1` |
| `--sheet` | 시트 이름 또는 번호 | `--sheet 영천` |
| `--addr-col` / `--facility-col` | 주소·시설물 컬럼명 직접 지정 | `--addr-col "소재지"` |
| `--repeat N` | 같은 질의 N회 반복 (일관성 측정). N ≥ 2이면 `dashboard/consistency/<시각>/`에 저장 | `--repeat 3` |
| `--out` | 결과 파일명 (기본: dashboard/pred.xlsx / 반복 시 dashboard/consistency/<시각>/pred_repeat.xlsx) | `--out pred_1020.xlsx` |
| `--reextract` | **재질의 없이** raw 원문에서 결과 파일만 다시 생성 | |
| `--raw-dir` | `--reextract`할 raw 폴더 지정 (일관성 결과 재추출 시) | `--raw-dir dashboard/consistency/20261020_1430/raw` |

`--reextract`는 추출 규칙(이 문서 5장)을 바꿨을 때만 씁니다. 평소에는 qa_runner.py가 raw 저장과 pred.xlsx 생성을 한 번에 처리합니다.

### 질의 방식

- API: `POST /api/chat/sessions/{임의 세션ID}/messages/stream`
- 헤더: `X-Device-Id: qa-runner` (실제 사용자 세션과 구분)
- 본문: `{"user_request": "{주소} {시설물} 건축 가능한가요?"}`
  - gold.xlsx에 `질의문` 컬럼이 있으면 그 문장을 그대로 보냅니다.
- 응답: SSE(Server-Sent Events) 스트림. 서버가 charset을 보내지 않으므로 바이트로 받아 UTF-8로 디코딩합니다.
- 타임아웃: 1건당 300초. 초과하거나 실패하면 `AI판정 = 오류`로 기록하고 다음 케이스로 넘어갑니다.

### 일관성 측정 ([AI 3]) — 동일 질의 반복 / 변형 질의

LLM 응답은 같은 질의에도, 같은 의도의 다른 표현에도 달라질 수 있습니다. 두 방식 중 하나를 선택합니다.

| 방식 | 보내는 질의 | 확인하는 것 | 명령 |
|---|---|---|---|
| **동일 질의 반복** | 같은 문장을 N회 (회차마다 새 세션) | 같은 입력에 대한 응답의 무작위성 | `python qa_runner.py gold.xlsx --header 1 --repeat 3` |
| **변형 질의** | 같은 의도를 다른 표현으로 바꾼 문장들을 1회씩 (새 세션) | 표현이 달라도 같은 판정·근거를 내는지 (표현 강건성) | `python qa_runner.py gold.xlsx --header 1 --variants` |

**변형 질의 문장 정하는 법** (우선순위 순)

1. 정답셋에 `질의문_변형1`, `질의문_변형2`, … 컬럼이 있으면 그 케이스는 **그 문장들**을 그대로 사용 (케이스마다 직접 작성할 때)
2. 없으면 **템플릿**에 주소·시설물을 넣어 생성. 템플릿은 `--variant-file 파일` 또는 화면의 ✏️ 변형 문장 편집(저장 시 `variants.txt`)으로 바꿀 수 있고, 지정하지 않으면 기본 5종을 사용합니다.

기본 변형 템플릿 5종 (`{주소}`, `{시설물}` 자리에 정답셋 값이 들어감)

| 변형 | 템플릿 | 표현 특징 |
|---|---|---|
| 1 | `{주소} {시설물} 건축 가능한가요?` | 기본 질의 (정확도 측정과 동일) |
| 2 | `{주소} 필지에 {시설물} 신축이 가능한지 알려주세요.` | '필지', '신축' 용어 |
| 3 | `{주소}에 {시설물} 지으려고 하는데 허가 받을 수 있을까요?` | 구어체, '허가' |
| 4 | `{시설물} 건축하려고 하는데 {주소} 땅이면 가능해?` | 어순 변경(시설물 먼저), 반말 |
| 5 | `{주소} 토지에서 {시설물} 건축허가 가능 여부를 검토해 주세요.` | 문어체, 검토 요청 |

**저장 위치** — 실행마다 새 폴더, 정확도용 `dashboard/raw/`·`dashboard/pred.xlsx`와 분리

```
dashboard/consistency/20261020_1430_반복/   또는   dashboard/consistency/20261020_1430_변형/
├─ raw/{case_id}_{회차}.json      응답 원문 (변형 질의는 회차 = 변형 번호)
├─ queries.json                   회차별 실제 질의문·변형 번호·정답판정·응답 시간 (재추출 시에도 유지)
├─ pred_repeat.xlsx               전체 질의 추출 결과
└─ consistency_report.xlsx        일관성 리포트 (자동 생성)
```

- 재추출: `python qa_runner.py gold.xlsx --reextract --raw-dir dashboard/consistency/20261020_1430_변형/raw`
- 반복·변형 결과 파일을 실수로 `qa_eval.py`에 넣어도 정확도 채점에는 1회차만 사용합니다.

**consistency_report.xlsx**

| 시트 | 내용 |
|---|---|
| 요약 | 질의 방식, 케이스 수, 케이스당 질의 수, 판정 일관성, 근거 완전 일치 비율, 근거 유사도 평균, 정답 일치율 평균 |
| 케이스별 | 아래 지표 + 질의별 판정·근거(`1회_판정`… 또는 `1변형_판정`…) |
| 변형별 | (변형 질의만) 변형 번호, 질의 예시, 최빈판정 일치율, 정답 일치율, 응답없음·되묻기 건수 |
| 전체질의 | 실제로 보낸 질의문과 추출 결과 전체 |

| 지표 | 의미 |
|---|---|
| 판정일관 | 한 케이스의 모든 질의 판정이 같으면 True |
| 최빈판정 / 판정일치율 | 가장 많이 나온 판정과 그 비율 (예: 5개 변형 중 4개 불가 → 불가, 0.8) |
| 정답일치율 | 그 케이스의 질의 중 정답판정과 같은 비율 |
| 판정이_다른_변형 | (변형 질의) 최빈판정과 다르게 나온 변형 번호와 판정 — 예: `변형4(가능)` |
| 근거완전일치 / 근거유사도_평균 | AI근거 (법령명, 조) 집합이 모두 같은지 / 질의 쌍별 Jaccard 유사도 평균 |
| 변형별 최빈판정 일치율 | 그 표현으로 물었을 때 케이스별 최빈판정과 같은 비율 — **낮은 변형이 시스템이 취약한 표현** |
| 변형별 정답 일치율 | 그 표현으로 물었을 때 정답과 같은 비율 |

판정 일관성이 낮은 케이스·변형은 정확도 수치도 질의 표현이나 실행 시점에 따라 달라질 수 있으므로, [AI 1]·[AI 2] 결과를 보고할 때 함께 확인합니다.

### 화면에서 실행 (qa_app.py → `/dashboard`)

명령어 대신 브라우저 화면에서 실행하고 결과를 볼 수 있습니다. 아래 사이드바·탭 설명은 QA 대시보드(`http://localhost:8501/dashboard`) 기준입니다.

```
pip install streamlit                 # 최초 1회
cd C:\Users\user\Desktop\nipa_ai_eval
streamlit run qa_app.py               # 브라우저에 http://localhost:8501 이 자동으로 열림
```

종료는 실행한 터미널에서 `Ctrl + C`를 누릅니다.

- 같은 폴더의 `.streamlit/config.toml`에 실행 설정이 들어 있습니다. 첫 실행 시 이메일 질문이 나오지 않고, 브라우저가 자동으로 열리며, 오른쪽 상단의 Deploy 버튼과 ⋮ 메뉴가 숨겨집니다.
- 자주 바꾸지 않는 설정은 사이드바 맨 아래 **⚙️ 설정**에 있습니다: 시스템 API 주소, 질의 1건 최대 대기(초), 질의문 형식(`{주소} {시설물} 건축 가능한가요?`), 넓은 화면, 새로고침, 캐시 비우기, 작업 폴더 정보.

**왼쪽 사이드바 (설정·실행)**

| 항목 | 설명 |
|---|---|
| 📂 정답셋 변경 | 기본은 폴더의 gold.xlsx. 버튼을 눌러 파일을 올리면 gold.xlsx로 저장. 헤더 행은 자동 인식 |
| 측정 종류 | 정확도 (1회) / 일관성 (반복·변형) |
| 질의 방식 (일관성) | 동일 질의 반복(반복 횟수 지정) / 변형 질의(✏️ 변형 문장 편집에서 템플릿 수정·저장 → variants.txt) |
| 실행할 케이스 | 비우면 전체. 일부만 고르면 그 케이스만 다시 질의하고, 정확도 모드에서는 나머지 케이스의 기존 결과를 유지 |
| ▶ 실행 | 진행 막대와 함께 1건씩 결과가 표에 쌓임. 끝나면 결과 탭이 자동 갱신 |

**결과 탭**

| 탭 | 내용 |
|---|---|
| 📊 [AI 1] 정확도 결과 | 지표 카드(판정 정확도·오허가율·오불허율·핵심근거 적중률·조문 F1·종합 정답률), 혼동행렬, 케이스별 표(틀린 케이스만 보기), **케이스 상세**(정답 근거와 AI 근거 비교, 누락·과잉 근거, 시스템 단계별 처리 과정, 응답 원문 JSON), `raw에서 다시 추출` 버튼, qa_result.xlsx 다운로드 |
| 🎯 [AI 2] 판단 F1 스코어 | 목표 F1·무응답 처리·중요도 가중치 설정, 종합 F1과 달성 여부, 4×4 혼동행렬, 유형별 16개 지표, 오탐·미탐 사례와 오탐 패턴, f1_result.xlsx 다운로드 |
| 🔁 [AI 3] 일관성 결과 | 실행 폴더 선택(최신순, 반복/변형 표시), 판정 일관성·근거 유사도, **변형(표현)별 결과**, 케이스별 회차·변형 비교(흔들린 케이스만 보기), 실제 보낸 질의문 전체, 리포트 다운로드 |
| 📋 정답셋 | 불러온 정답셋과 인식된 주소·시설물 컬럼, 실제로 보낼 질의문 예시 |

**실행은 백그라운드에서 진행됩니다.** ▶ 실행을 누르면 화면이 `qa_runner.py`를 별도 프로세스로 띄우고, 화면은 진행 상황 파일(`run_status.json`)을 2초마다 읽어 상단 패널에 보여 줍니다.

- 실행 중에 **새로고침하거나 탭을 옮기거나 브라우저를 닫아도 실행은 계속**됩니다. 다시 열면 진행 상황이 그대로 보입니다.
- 상단 패널: 진행률, 지금 질의 중인 문장, 경과 시간, 지금까지 결과. 끝나면 ✅ 완료(초록) / ⏹ 중지됨·⚠️ 오류(주황, 로그 마지막 15줄 표시)로 바뀌고 결과 탭이 자동으로 갱신됩니다.
- **⏹ 중지**: 진행 중인 질의가 끝나면 멈춥니다. 그때까지의 결과는 저장됩니다.
- **↻ 이어서**: 중지·오류로 멈춘 실행은 패널의 이어서 버튼으로 남은 질의만 다시 돌립니다. 이미 정상 응답을 받은 질의는 건너뛰고, 결과는 같은 폴더(일관성) 또는 같은 pred.xlsx(정확도)에 합쳐집니다. 명령어로는 `--resume`(일관성은 `--run-dir 폴더`도 함께)입니다.
- 실행 중에는 ▶ 실행 버튼이 "⏳ 실행 중…"으로 잠겨 동시에 두 번 실행되지 않습니다(다른 PC에서 접속해도 동일).
- 러너의 출력은 `run.log`에 남습니다. 러너가 20초 넘게 응답이 없으면 비정상 종료로 표시합니다.
- 정확도 모드에서 케이스 일부만 고르면 그 케이스만 다시 질의하고 나머지 기존 결과는 유지하며, 끝나면 `qa_result.xlsx`도 다시 만듭니다.

화면에서 실행한 결과도 명령어 실행과 **같은 위치**(`dashboard/` 아래 `raw/`, `pred.xlsx`, `qa_result.xlsx`, `consistency/<시각>/`)에 저장되므로, 두 방식을 섞어 써도 됩니다. 

## 4. raw JSON 구조

`dashboard/raw/{case_id}_{회차}.json`은 시스템이 보낸 이벤트를 순서대로 담은 배열입니다.

```json
[
  {"event": "orc.start",    "data": {"session_id": "...", "build": "...", "contract_version": "..."}},
  {"event": "orc.trace",    "data": {"node": "permit_parcel", "message": "도로 접도를 분석하는 중입니다"}},
  {"event": "orc.response", "data": {"event": "parcel",    "data": { ... 필지 정보 ... }}},
  {"event": "orc.response", "data": {"event": "stage",     "data": { ... 단계별 결과 ... }}},
  {"event": "orc.response", "data": {"event": "diagnosis", "data": { ... 최종 진단 ... }}},
  {"event": "orc.response", "data": {"event": "reply",     "data": {"reply": "되묻는 문장"}}},
  {"event": "orc.end",      "data": {"trace_id": "...", "sub_status": { ... }}}
]
```

| 이벤트 (`orc.response`의 `data.event`) | 내용 | 추출에 사용 |
|---|---|---|
| `intent` | 질의 의도 (예: `permit_review`) | – |
| `parcel` | 주소 검색 결과, PNU, 토지대장·토지이용계획 | – |
| `stage` | 검토 단계별 상태·판정·법령. 같은 단계가 진행 중/완료로 여러 번 옵니다 | ✅ |
| `diagnosis` | 최종 진단 (판정, 위반 조건, 보고서 문장) | ✅ |
| `reply` | 진단 없이 되묻는 답변 (주소를 못 찾은 경우 등) | ✅ |

### `stage` 주요 키

| 키 | 의미 |
|---|---|
| `id` | 단계 ID: `zone_use`(용도지역·토지이용계획), `development_permit`(개발행위허가·접도), `building_permit`(건폐율·용적률), `civil_procedure`(민원절차) |
| `status` | `pending` → `running` → `done` |
| `verdict` | `possible` / `impossible` / `null` |
| `detail.laws` | 이 단계에서 인용한 법령 목록 |
| `detail.basis` | 판단 근거 문장 |

### `diagnosis.data` 주요 키

| 키 | 의미 |
|---|---|
| `judgment.verdict` | 최종 판정 (접도 포함) |
| `judgment.matrix_gate.final` | 용도지역 행위제한만 본 판정 (접도 제외) |
| `judgment.conditions[]` | 적용한 조건. `status`(pass/fail), `source`(조문), `natural`(조건 설명), `actual`/`standard`(실측/기준) |
| `judgment.violations[]` | 위반 내용 문장 |
| `judgment.per_zone[]` | 용도지역·구역별 판정 |
| `report.band.line` | 결론 한 줄 |
| `report.band.deny_reasons[]` | 불허 사유 (법령 포함 문장) |
| `report.card.headline` | 화면 상단 요약 문장 |
| `report.card.summary` | 법령을 포함한 설명 문장 |
| `report.detail_md` | 상세 설명 (마크다운) |

## 5. pred.xlsx 컬럼별 추출 기준

아래 경로에서 `diagnosis`는 `diagnosis` 이벤트의 `data`, `stage`는 `status = done`인 `stage` 이벤트의 `data`를 뜻합니다.

| 컬럼 | 추출 경로 | 규칙 |
|---|---|---|
| **AI판정** | `diagnosis.judgment.verdict` | 값이 없으면 `diagnosis.status`를 씁니다. `diagnosis`가 없을 때 `reply` 이벤트가 있으면 **`되묻기`**, 둘 다 없으면 **`응답없음`**, 통신 실패면 **`오류`**로 기록합니다. |
| **AI용도지역판정** | `diagnosis.judgment.matrix_gate.final` | `O`(가능) / `X`(불가) / `?`(검토 필요). 접도를 제외하고 용도지역만 본 판정입니다. |
| **AI불가근거** | ① `diagnosis.judgment.conditions[]` 중 `status == "fail"`인 항목의 `source`<br>② `verdict == "impossible"`인 `stage`의 `detail.laws`<br>③ `diagnosis.report.band.deny_reasons[]` | ①+②+③ 순서로 합칩니다. ③은 2번(도시계획시설), 7번(산업시설구역)처럼 구역 때문에 불허된 경우에 근거가 들어오는 곳입니다. |
| **AI허용근거** | `id == "zone_use"`인 `stage`의 `detail.laws` | 용도지역·토지이용계획 검토에서 인용한 허용 근거입니다. 가축분뇨법·문화유산법처럼 함께 걸린 구역의 법령도 포함됩니다. |
| **AI근거** | AI판정에 따라 선택 | `impossible`이면 **AI불가근거**, 그 외면 **AI허용근거**를 씁니다. **채점에 사용하는 컬럼입니다.** |
| **AI전체인용법령** | 모든 `stage`의 `detail.laws` + 모든 `conditions[].source` | 판정과 상관없이 시스템이 언급한 법령 전체(참고용)입니다. |
| **AI요약** | `diagnosis.report.card.headline` | 없으면 `report.band.line`을 씁니다. `되묻기`일 때는 `reply` 문장을 넣습니다. |
| **AI설명** | `diagnosis.report.card.summary` | 법령을 포함한 설명 문장입니다. |
| **AI적용용도지역** | `diagnosis.scale.pieces[].zone` (없으면 `scale_by_zone[].zone`) | 건폐율·용적률을 적용한 용도지역·지구. 예: 일반상업지역, 자연취락지구 |
| **AI건폐율** | `diagnosis.scale.bcr` | % 숫자. 예: 80 |
| **AI용적률** | `diagnosis.scale.far_max` (없으면 `far_min`) | % 숫자. 예: 1300 |
| **AI층수** | `building_permit` 단계 `detail.markdown`의 "적용 기준" 표 → 층수 칸 | 적용 용도지역 행 우선, 비어 있으면 바탕 용도지역 행. 예: 제한 없음, 4층 이하 |
| **AI규모근거** | `diagnosis.scale.specials[].basis`(특례) 또는 `scale.ordinance` + 표 아래 "층수는 …를 따릅니다" 문장 | 예: [영천시 도시계획조례 제56조·제62조] [국토의 계획 및 이용에 관한 법률 시행령 제71조] |
| **AI규모요약** | 위 값을 한 줄로 | 예: 자연녹지지역 · 건폐율 20% · 용적률 100% · 층수 4층 이하 (영천시 도시계획조례 제56조·제62조; …) |
| **AI필요허가** | 사용자에게 보이는 답변 문장(단계별 `text`·`summary`·`markdown`·`basis`·`laws`·`warnings`, 최종 `report`)에서 허가 종류를 찾음 | 1차 사업 허가 10종으로 분류(아래 표). 내부 지시문(parcel 등)과 자동 생성 '확인할 사항(checks)'은 제외. 예: 개발행위허가(단순 형질변경); 건축허가(신축) |
| **AI허가근거** | 위에서 허가를 찾은 문장 일부 | 예: 산지전용허가: …산지전용허가 때 검토… |

### 공통 처리

- 같은 단계가 여러 번 내려오므로, 법령은 **중복을 제거하고 처음 나온 순서를 유지**합니다.
- 각 법령은 `[법령명 제N조]`처럼 대괄호로 감싸 공백으로 이어 붙입니다. 채점 단계에서는 이 대괄호 단위로 법령을 인식합니다.

### 그 밖의 컬럼

| 컬럼 | 내용 |
|---|---|
| `case_id`, `회차` | 정답셋의 케이스 번호, 반복 회차 |
| `질의` | 실제로 보낸 질의문 |
| `session_id` | 시스템 세션 ID (개발팀 로그 조회용) |
| `소요초` | 응답 시간 |
| `오류` | 통신 오류 메시지 |

`--reextract`로 만든 pred.xlsx에는 `질의`, `session_id`, `소요초`, `오류` 컬럼이 없습니다.

### 예시

| case | AI판정 | AI근거 | 근거가 나온 곳 |
|---|---|---|---|
| 6 | impossible | [건축법 제44조 제1항] [건축법 시행령 제3조의3 제1호] | 조건 fail + 개발행위허가 stage |
| 2 | impossible | [도시·군계획시설 부지라 단독주택 불허 (국토의 계획 및 이용에 관한 법률 제64조)] | `report.band.deny_reasons` |
| 5 | possible | [국토의 계획 및 이용에 관한 법률 시행령 … 제71조 …] [문화유산 … 제13조] … | `zone_use` stage |
| 8 | 되묻기 | (없음) | `reply`: 주소 검색 실패 |

## 6. 채점 (qa_eval.py)

### gold.xlsx 형식

| case_id | 주소 | 시설물 | 정답판정 | 근거 | (선택) 필수근거 |
|---|---|---|---|---|---|
| 6 | 경상북도 영천시 조교동 43-12 | 단독주택 | 불허 | … [건축법 제44조 제1항] | |

- 근거는 `[법령명 제N조]` 또는 `[법령명 별표 N]` 형식으로 적습니다.
- 첫 줄이 제목이면 2번째 줄을 헤더로 자동 인식합니다.
- `필수근거`가 없으면 `근거` 전체를 핵심근거로 봅니다.
- **정답 필요허가(선택)**: `정답_필요허가` 컬럼에 필요한 허가를 `;` `,` `/` 줄바꿈 중 하나로 구분해 적습니다. 예: `개발행위허가(단순 형질변경); 건축허가(신축); 산지전용허가`. 띄어쓰기·줄임("건축허가", "도로 점용허가")도 아래 규칙으로 같은 허가로 인식하며, 10종에 없는 항목은 `허가_미분류`에 표시됩니다.

  | 허가 종류 (1차 사업) | 인식 규칙 (공백 무시) |
  |---|---|
  | 개발행위허가(토지분할 등) | 토지분할, 분할허가 |
  | 개발행위허가(단순 형질변경) | 형질변경 |
  | 개발제한구역 내 행위허가 | "개발제한구역 … 행위허가" (20자 이내) |
  | 개발제한구역 내 건축허가 | "개발제한구역 … 건축허가" (20자 이내) |
  | 건축허가(신축) | 건축허가 (개발제한구역 내 건축허가로 잡힌 부분 제외) |
  | 공장설립승인(허가) | 공장설립 |
  | 농지전용허가 / 초지전용허가 / 산지전용허가 | 농지전용 / 초지전용 / 산지전용 |
  | 도로 점용허가 | 도로점용 |

- **정답 규모(선택)**: `정답_건폐율`, `정답_용적률`, `정답_층수`, `정답_용도지역` 컬럼에 적으면 그 값을 씁니다. 없으면 `답변…` 컬럼 문장에서 자동으로 찾습니다 — 예: "허용 건축 규모 (일반상업지역 기준) … **건폐율**: 80.0% … **용적률**: 1300.0%". 층수는 `정답_층수`(예: 4층 이하, 제한 없음)로 적어야 채점됩니다.

### 정규화

| 항목 | 처리 |
|---|---|
| 판정 | `불허`·`불가`·`impossible` → 불가 / `가능`·`허가`·`possible` → 가능 / `조건부`·`conditional` → 조건부 |
| 법령명 띄어쓰기 | 무시 (`도시계획 조례` = `도시계획조례`) |
| 약칭 | `국계법`·`국토계획법` → 국토의 계획 및 이용에 관한 법률, `산집법`·`산업집적법`, `개발제한구역법`, `산업입지법`, `가축분뇨법`, `문화유산법` (`LAW_ALIAS`에 추가 가능) |
| 조문 단위 | **조까지만 비교** (`제44조 제1항` = `제44조`). `제7조의 2` = `제7조의2`. 별표는 `별표N` |
| 생략 표기 | `제33조 별표 8` → 앞 법령 유지, `같은 법 시행령`·`· 시행령`·`· 영` → 직전 법률의 시행령 |

| 지표 | 의미 |
|---|---|
| 필요 행위허가 정밀도 | AI가 언급한 허가 중 정답에도 있는 비율 (과잉 언급이 적을수록 높음) |
| 필요 행위허가 재현율 | 정답에 필요한 허가 중 AI가 언급한 비율 (누락이 적을수록 높음) |
| 필요 행위허가 F1 | 정밀도·재현율의 조화평균 |

> 현재 시스템 응답에는 **허가별 가능·불가 판정**이 없어(내부 지시문에 "전용 가능/불가를 단정하지 말라"는 문구가 있음) 이 지표는 "필요한 허가를 짚었는지"만 봅니다. 허가별 판정 정확도를 재려면 진단 결과에 허가별 항목(예: `permits: [{종류, 필요, 판정, 근거}]`) 추가가 필요합니다. 필요 허가는 종합 정답률에는 포함하지 않습니다.

규모 지표는 **정답이 가능·조건부**이고 정답셋에 값이 적힌 케이스만 대상으로 하며(불가는 건폐율·용적률·층수가 정해지지 않으므로 시스템이 값을 내더라도 채점 제외)(지표 이름 옆 "대상 N건"), 정답 값이 없는 케이스는 `규모_일치`가 빈칸입니다. 규모 근거 법령(조례 제56조·제62조 등)은 `AI규모근거`에 따로 두고, 조문 F1·핵심근거 채점에 쓰는 `AI근거`에는 섞지 않습니다(정답 근거에 없는 조문이라 과잉근거로 잡히는 것을 막기 위해).

`케이스별` 시트에는 케이스마다 **누락근거**(정답에는 있는데 AI가 빠뜨린 것)와 **과잉근거**(AI만 인용한 것)가 표시됩니다.

### 핵심근거 적중률 계산 방식

gold.xlsx의 `근거` 컬럼과 pred.xlsx의 `AI근거` 컬럼을 케이스별로 비교합니다.

1. **법령 추출**: 두 컬럼에서 대괄호 `[...]` 안의 법령을 **(법령명, 조)** 단위로 뽑습니다. 띄어쓰기·약칭·항·호 차이는 정규화해서 무시합니다.
   - 정답 `[건축법 제44조 제1항]` → (건축법, 44)
   - AI `[건축법 제44조 제1항] [건축법 시행령 제3조의3 제1호]` → (건축법, 44), (건축법시행령, 3의3)
2. **케이스별 적중**: 정답 근거 중 **하나라도** AI근거에 있으면 적중(`핵심근거_적중 = True`)입니다. 위 예시는 (건축법, 44)가 겹치므로 적중입니다.
3. **적중률**: 적중 케이스 수 ÷ 전체 케이스 수. `되묻기`·`응답없음`처럼 근거가 없는 케이스도 분모에 들어가며 미적중으로 계산됩니다.

주의할 점

- **`필수근거` 컬럼이 있으면 그것을 우선 사용합니다.** gold.xlsx에 이 컬럼을 추가하면 `근거` 대신 필수근거만 기준으로 봅니다. 정답 근거가 3개여도 판정을 결정하는 근거가 1개뿐이면 그 1개만 적으면 되고, 그러면 보조 근거를 빠뜨렸다는 이유로 미적중이 되지 않습니다.
- **판정 일치 여부와는 별개입니다.** 판정이 틀려도 근거가 겹치면 적중으로 계산됩니다. 판정과 근거가 모두 맞은 경우만 보려면 `종합 정답률`을 봅니다.
- **"하나라도 겹치면 적중"이므로 관대한 지표입니다.** 정답 근거를 빠짐없이 인용했는지는 `조문_재현율`, 불필요한 인용 없이 정확했는지는 `조문_정밀도`로 따로 확인합니다.

## 7. [AI 2] 사전 진단 판단 F1 스코어 (qa_f1.py)

[AI 1]과 **같은 질문셋·정답셋(gold.xlsx)과 AI 결과(pred.xlsx)**를 사용합니다. 추가 질의는 하지 않습니다.

```
pip install scikit-learn                                          # 최초 1회 (없어도 동일 계산으로 동작)
python qa_f1.py gold.xlsx dashboard/pred.xlsx                               # 기본: 목표 95%
python qa_f1.py gold.xlsx dashboard/pred.xlsx --weights 불가=2,가능=1         # 유형별 중요도 가중치
python qa_f1.py gold.xlsx dashboard/pred.xlsx --no-answer 검토필요             # 무응답을 검토필요로 간주
```

화면에서는 **🎯 [AI 2] 판단 F1 스코어** 탭에서 같은 내용을 보고 옵션을 바꿀 수 있습니다.

### 판단 유형 4종

시스템 `diagnosis.judgment.verdict` 값 기준입니다(화면 표시 문구는 시스템 프론트 코드와 동일).

| 유형 | 시스템 값 | 화면 표시 | 정답셋 `정답판정`에 쓸 수 있는 표기 |
|---|---|---|---|
| 가능 | `possible` | 허가 가능 | 가능, 허가, 허용 |
| 조건부 | `conditional` | 조건부 가능 | 조건부, 조건부 가능 |
| 불가 | `impossible` | 허가 불가 | 불가, 불허 |
| 검토필요 | `needs_review` | 검토 필요 | 검토필요, 검토 필요, 확인필요 |

- 정답셋에 없는 유형은 사례 수가 0이라 지표가 **산출 불가**로 표시되고 가중평균에서 빠집니다. 4종을 모두 평가하려면 정답셋에 유형별 사례를 넣어야 합니다.
- **무응답**(되묻기·응답없음·오류)은 4종 어디에도 넣지 않고 혼동행렬의 `무응답` 열에 따로 표시합니다. 해당 실제 유형의 **미탐(FN)**으로만 계산되며, 어느 유형의 오탐(FP)도 아닙니다. `--no-answer 검토필요`로 바꾸면 검토필요로 판단한 것으로 간주합니다.

### (5) TP·FP·FN·TN과 4×4 혼동행렬

`sklearn.metrics.confusion_matrix(정답유형, AI유형, labels=[가능, 조건부, 불가, 검토필요, (무응답)])`로 혼동행렬을 만듭니다. **행 = 실제(정답), 열 = 판단(AI)**입니다. 유형 t에 대해:

| 값 | 정의 | 혼동행렬에서 |
|---|---|---|
| TP | t로 판단 + 실제도 t | 대각선 [t, t] |
| FP (오탐) | t로 판단 + 실제는 다른 유형 | t **열** 합계 − TP |
| FN (미탐) | 다른 유형(또는 무응답)으로 판단 + 실제는 t | t **행** 합계 − TP |
| TN | 다른 유형으로 판단 + 실제도 다른 유형 | 전체 − TP − FP − FN |

### (6) 유형별 지표 (4종 × 4지표 = 16개 값)

| 지표 | 산정식 |
|---|---|
| Precision(%) | TP / (TP + FP) × 100 |
| Recall(%) | TP / (TP + FN) × 100 |
| Specificity(%) | TN / (TN + FP) × 100 |
| F1 Score(%) | 2 × Precision × Recall / (Precision + Recall) |

- 분모가 0이면 **산출 불가**로 표시합니다(예: AI가 그 유형으로 한 번도 판단하지 않으면 Precision 산출 불가).
- 실제 사례가 있는데 한 번도 맞히지 못하면 F1 = 0으로 계산합니다(sklearn `zero_division=0`과 동일).
- 보조로 `오탐률(%) = 100 − Specificity`를 함께 표시합니다.
- 계산 결과는 `sklearn.metrics.precision_recall_fscore_support`와 교차 검증했습니다.

### (7) 종합(가중평균) F1과 목표 달성 판정

- **가중평균 F1(%) = Σ(유형별 F1 × 유형별 사례 수) / 전체 사례 수** — 사례 수 = 실제(정답) 기준 TP + FN
- **중요도 가중치**(선택, `--weights` 또는 화면 토글): Σ(F1 × 사례 수 × 중요도) / Σ(사례 수 × 중요도). 중요도를 모두 1로 두면 가중평균 F1과 같습니다. 예를 들어 오허가 위험이 큰 `불가`에 2를 주면 불가 유형의 성능이 종합 점수에 2배로 반영됩니다.
- 참고용으로 매크로 F1(유형별 F1 단순평균)도 함께 표시합니다.
- **종합 F1 ≥ 목표(기본 95%)이면 달성**으로 판정합니다.

현재 10건 기준 예시: 가능 F1 100.00 (4건), 불가 F1 90.91 (6건, 무응답 1건이 미탐) → (100×4 + 90.91×6) / 10 = **94.55% → 미달성**

### (8) 오탐·미탐 사례 분석

f1_result.xlsx `오탐미탐사례` 시트에 정답과 AI 판단이 다른 케이스를 모두 나열합니다.

| 열 | 내용 |
|---|---|
| 오류 구분 | 예: `불가 미탐(FN) / 가능 오탐(FP)` — 한 케이스가 실제 유형의 미탐이자 판단 유형의 오탐 |
| 추정 원인 | 결과로 자동 분류한 원인 (아래 표) |
| 정답 근거 / AI 근거 / AI 요약 | 원인 확인용 |
| 확인 원인 · 개선사항 · 후속 계획 | **사람이 검토 후 작성** |

| 추정 원인 | 분류 조건 |
|---|---|
| 입력 오류 — 주소 검색 실패 | AI가 되묻기로 응답하고 위치·주소 관련 문구 포함 |
| 시스템 무응답/오류 | 진단 결과 없음, 통신 오류 |
| 모델 신뢰도 부족 — 판단 보류 | AI가 검토필요로 판단 |
| 불확실성 인식 부족 | 정답이 검토필요인데 AI가 단정 판단 |
| 룰셋 적용 누락 — 정답 근거 법령 미검토 | 정답 불가/조건부 → AI 가능, AI 전체 인용 법령에 정답 근거 법령 없음 |
| 룰 판정 오류 — 법령 검토했으나 허용 판단 | 정답 불가/조건부 → AI 가능, 정답 근거 법령은 인용함 |

| 용도지역·구역 판단 상이 | 정답 가능/조건부 → AI 불가, 불허 근거가 구역·시설·지역 |
| 조건부 여부 판단 상이 | 가능↔조건부, 불가↔조건부 |

`오탐패턴` 시트는 **특이도 보조 분석**입니다. AI가 잘못 판단한 유형(오탐)이 실제로 어떤 유형에서 왔는지, 건수와 주요 원인을 묶어 보여 줍니다. Specificity가 낮은 유형부터 이 시트를 보고 개선 항목을 정하면 됩니다.

- **가능 케이스의 F1이 낮음**: 허용근거에 함께 걸린 구역의 법령(가축분뇨법, 문화유산법 등)도 들어 있기 때문입니다. 대표 지표로는 핵심근거 적중률을 봅니다.
- **API 변경 주의**: 응답 구조(`contract_version`)가 바뀌면 5장의 추출 경로를 다시 확인해야 합니다. 현재 기준은 `contract_version: 2026-10-15`입니다.

#### 정답셋 작성 규칙 (적용법령 · 근거조문)

**여러 값 구분** — 세미콜론(`;`) 권장. 쉼표(`,`), 셀 안 줄바꿈(Alt+Enter), `["A", "B"]` 목록 형식도 인식합니다.

| 쓰는 방식 | 인식 |
|---|---|
| `국토계획법; 국토계획법시행령` | ✅ (권장) |
| `국토계획법, 국토계획법시행령` / 셀 안 줄바꿈 / `["국토계획법", "국토계획법시행령"]` | ✅ |
| `국토계획법 / 국토계획법시행령` (슬래시) | ❌ 한 덩어리로 읽힘 |
| `국토계획법·건축법` (가운뎃점) | ❌ 한 덩어리로 읽힘 |
| `국토계획법 국토계획법시행령` (띄어쓰기만) | ❌ 한 덩어리로 읽힘 |

**적용법령** — 약칭·정식명·띄어쓰기 차이는 같은 법으로 봅니다 (`국토계획법` = `국계법` = `국토의 계획 및 이용에 관한 법률`, `국계법 시행령` = `국토계획법시행령`).

**근거조문** — 규격서 형식인 `법령명.조.항` 권장 (예: `건축법.2.1; 건축법.44`). 법령 문장 표기도 인식합니다.

| 쓰는 방식 | 인식 결과 |
|---|---|
| `건축법.44.1` / `건축법.44` / `국토계획법시행령.별표23` | ✅ 그대로 (권장) |
| `건축법 제44조 제1항` / `건축법 제44조제1항제2호` | ✅ 건축법.44.1 (호·목은 버림) |
| `국토계획법 제76조의3` | ✅ 국토계획법.76의3 |
| `건축법 44조 1항` ("제" 없음) | ❌ 인식 안 됨 |
| `건축법-44-1` (하이픈) | ❌ 인식 안 됨 |
| `건축법 44.1` (법령명 뒤 띄어쓰기) | ❌ 법령명이 잘못 붙음 |

- 점 표기는 법령명 **바로 뒤에** 점을 붙이고, 문장 표기는 **"제○조"처럼 "제"를 붙여야** 인식됩니다.
- 인식되지 않으면 오류는 나지 않지만 그 값이 빠진 것으로 처리되어 보조 지표(AI1) · 단서 조건 근거 조문(AI4) · 환각 판정(AI5)이 불일치로 나옵니다.
- AI1·AI4·AI5 정답셋, AI5 조문 DB(`law_article_db.csv`의 조문ID)에 모두 같은 규칙이 적용됩니다.

### 9-4. AI3 8단계 로그 재구성

시스템이 단계 로그를 직접 내보내지 않아 응답에서 재구성합니다.

| 단계 | 근거 | 비교 필드 |
|---|---|---|
| ① 질의 파싱 | intent, facility_match | 실행·데이터소스 |
| ② 대상 필지(PNU) 조회 | 위치 검색 도구 호출(INTEGRATED_LOCATION_SEARCH) | 데이터소스·조회키·결과건수 |
| ③ 토지특성 조회 | parcelInfo(ATTR)·경사·접도 도구 호출 | 데이터소스·조회키·결과건수 |
| ④ 용도지역 판정 | matrix_gate.zone_results (용도지역별 O/X, final) | + 중간 판정값 |
| ⑤ 규제구역 조회 | land_regulation·spatial_regulation 결과, 용도지역지구 | + 중간 판정값(규제구역 집합) |
| ⑥ 적용 법령·조례 검색 | 단계별 `detail.laws` | 검색 법령 집합 |
| ⑦ 룰셋 적용 | judgment.conditions / matrix_gate | 적용 룰셋 ID 집합 |
| ⑧ 최종 판단 | judgment.verdict | 중간 판정값(판단 유형) |

타임스탬프·소요시간·요청ID(session_id, trace_id)는 비교하지 않습니다. 1회차가 기준이며 기준 회차도 일치 수행에 포함합니다. 응답 오류 회차는 불일치로 셉니다.

### 9-5. 채점 규칙 요약

- **AI1**: 판단 유형 일치 수 ÷ 전체. 보조: 적용 법령(정답 법령이 응답에 모두 있으면 일치), 근거 조문(집합 일치).
- **AI2**: 2×2 혼동행렬 → 유형별 Precision·Recall·F1 → Σ(F1 × 정답 질의 수) ÷ 전체. 보조: 원문과 같은 판단을 낸 변형 질의 비율.
- **AI3**: 위 표의 비교 필드가 모두 같으면 일치. 보조: 5회 모두 일치한 사례 비율, 불일치 단계별 건수.
- **AI4**: 판정 결과 일치 **그리고** 단서 조건 근거 조문 집합 일치(순서 무시, 한쪽이 항을 생략하면 조 단위 비교). 보조: 보완사항(키워드 80 % 이상 정확 / 일부 부분 / 없음 불일치), 필요 행정절차(집합).
- **AI5**: ① 인용 조문이 조문 DB에 없음 ② 근거 조문 없음 ③ 정답 조문셋과 교집합 없음 ④ 정답 적용 법령이 응답에 없음 — 하나라도 해당하면 환각 1건. ⑤ 논리 불일치(보조): R1 가능 판정인데 위반·불허 사유 존재, R2 불가 판정인데 위반·불허 사유 없음, R3 결론 문장이 판정과 반대.

`qa_runner.extract`나 `qa_eval`의 법령 정규화를 바꾸면 두 기능 결과가 함께 바뀝니다.


## 10. 판단 여부 점검

질의를 일괄로 보내 시스템이 **허가 가능 / 허가 불가로 판단했는지, 판단하지 못했는지**만 확인합니다. 정답셋은 필요 없습니다. `/check` 주소로 접속해서 씁니다.

### 판단 구분

| 구분 | 시스템 응답 | 표시 |
|---|---|---|
| **판단함** | `judgment.verdict` = possible · conditional | 허가 가능 |
| **판단함** | `judgment.verdict` = impossible | 허가 불가 |
| 판단 못함 | `judgment.verdict` = needs_review | 검토 필요 — 미확정 조건, 용도지역 `?`, 결론 문장을 사유로 표시 |
| 판단 못함 | 진단 없이 되물음(reply) — 예: 주소를 찾지 못함 | 되묻기 — 시스템 메시지 표시 |
| 판단 못함 | 진단도 되물음도 없음 | 응답 없음 |
| 판단 못함 | HTTP 오류·시간 초과 | 통신 오류·시간 초과 |
| 판단 못함 | 그 밖의 verdict 값 | 기타(값) |

판단률(%) = 판단함 ÷ 전체 × 100 (소수점 셋째자리 이하 버림)

### 질의 목록

- **📂 질의 파일 올리기**: CSV·XLSX(`질의문` 컬럼, 없으면 `주소`·`시설물` 컬럼으로 ⚙️ 설정의 질의문 형식에 맞춰 생성. ID 컬럼 `사례ID`·`질의ID`·`case_id`·`ID`가 있으면 사용) 또는 TXT(한 줄에 질의 하나). `check_data/queries.<확장자>`로 저장됩니다.
- 이미 있는 `gold.xlsx`, `spec_data/testset_ai*.csv`도 목록에서 바로 고를 수 있습니다.

### 결과 (check/<시각>/)

| 파일 | 내용 |
|---|---|
| `raw/<ID>.json` | 응답 원문 |
| `queries.json` | 질의·소요 시간·오류 |
| `check_result.xlsx` | `요약`, `미판단유형별`, `질의별`, `판단못함_목록` 시트 |
| `summary.json` | 전체·판단함·판단 못함·판단률 |

### 명령어

```
python verdict_check.py --input check_data/queries.csv
python verdict_check.py --input gold.xlsx
python verdict_check.py --rescore check/20261022_183000     # 재질의 없이 결과 엑셀만 다시 만듦
```

## 11. 화면 주소 (URL)

화면 전환 메뉴는 숨겨져 있고, 주소로 구분합니다. 시험원은 기본 주소만 쓰고, 나머지는 내부에서 주소로 직접 접속합니다.

| 주소 | 화면 | 용도 |
|---|---|---|
| `http://<서버>:8501/` | 규격서 시험 (AI 1 ~ AI 5) | 시험원용 기본 화면 |
| `http://<서버>:8501/dashboard` | QA 대시보드 (정확도·F1·일관성) | 내부용 |
| `http://<서버>:8501/check` | 판단 여부 점검 | 내부용 |

`/spec`으로 들어와도 기본 화면(`/`)으로 열립니다. 실행 상태 파일은 세 화면이 함께 쓰므로 한 화면에서 실행 중이면 다른 화면의 실행 버튼도 잠깁니다.

## 12. 규격서 시험 AI 6 · AI 7 (결과 파일 채점)

| 항목 | 지표 | 목표 | 결과 표기 |
|---|---|---|---|
| 2-6 AI6 | 자연어 기반 지도 제어 정확도 | 90 % 이상 | 소수점 둘째자리 이하 버림 |
| 2-7 AI7 | 자연어 기반 3D 시뮬레이션 명령 정확도 | 90 % 이상 | 소수점 둘째자리 이하 버림 |

지도·3D 명령은 실행 후 화면 상태 확인과 프론트 화면 캡처가 필요해서, **자동 실행은 아직 연결하지 않았습니다.** 시스템 실행 결과를 결과 파일로 올리면 규격서 기준으로 채점합니다. 응답 구조(같은 채팅 API로 처리되는지, 지도·3D 상태가 응답에 담기는지)를 확인하면 실행기를 연결합니다.

### 데이터 (spec_data/)

| 파일 | 컬럼 |
|---|---|
| `testset_ai6.csv` / `testset_ai7.csv` | 사례ID, 명령유형, 명령문 (AI7은 + 선행상태) |
| `answer_ai6.csv` / `answer_ai7.csv` | 사례ID, 명령유형, 정답의도, 정답파라미터, 정답시나리오 |
| `result_ai6.csv` / `result_ai7.csv` | 사례ID, 해석의도, 해석파라미터, 실행대상기능, 실행결과, 실행상태, 캡처파일, 시나리오판정(선택) |

- 의도는 `;`로 구분: `지도 이동; 규제 저촉 분석; 분석 결과 표출`
- 파라미터·시나리오는 `키=값; 키=값` (규격서 예시의 `위치 ○○ / 분석대상 ○○`, JSON 객체도 읽음)
- 캡처 파일은 경로를 적으면 사례 상세에 이미지가 표시됨 (`spec_data/captures/` 아래 파일명만 적어도 됨)

### 채점

1. **① 의도**: 정답 의도 집합과 정확히 같아야 일치 (하나라도 빠지거나 더 있으면 오류)
2. **② 핵심 파라미터**: 정답의 키마다 결과 값이 같아야 일치 (공백·가운뎃점·'번지' 표기 차이 무시)
3. **③ 실행**: 정답 시나리오의 키마다 실행 결과가 같고 실행 상태가 '완료'여야 일치. 결과 파일의 `시나리오판정`에 O/X를 적으면 그 값을 우선 사용 (GIS 전문가·시험원 판정용)

셋 다 일치하면 정상 수행. 오류 원인은 ① → ② → ③ 순서로 처음 어긋난 기준으로 분류합니다(AI6: 의도 해석 / 핵심 파라미터 추출 / GIS 지도 제어 실행, AI7: … / 3D 시뮬레이션 명령 실행). 결과 화면에 총괄 결과, 명령 유형별 세부 결과, 오류 원인 유형별 건수가 표로 나옵니다.

### 화면

규격서 시험(`/`) → 시험 항목 AI6·AI7 → 📂 시험 데이터에서 시험셋·정답셋·결과 파일을 올림 → **▶ 결과 채점**. 결과는 `spec/AI6/<시각>/` (command_log_ai6.jsonl, meta.json, result.xlsx, summary.json)에 저장됩니다.

### 12-1. 자동 실행 연결 전 확인 사항 (AI6·AI7 담당자에게 요청)

| # | 확인할 것 | 왜 필요한지 | 상태 |
|---|---|---|---|
| 1 | 지도·3D 명령을 보내는 **API 주소**: AI1~5와 같은 채팅 API(`/api/chat/sessions/{id}/messages/stream`)로 처리되는지, 공간분석·3D 에이전트용 주소가 따로 있는지 | 실행기가 명령을 어디로 보낼지 결정 | 미확인 (2026-10-29, 작업 환경 네트워크 차단으로 직접 확인 못 함) |
| 2 | 명령 1건의 **응답 원문 샘플** 1~2건 (AI6 지도 제어, AI7 3D 시뮬레이션 각각) | 응답에서 해석 의도·핵심 파라미터·실행 대상 기능을 어떤 필드로 뽑을지 매핑 | 미확인 |
| 3 | 실행 후 **지도·3D 상태**(이동 위치, 분석 결과 표출, 생성 건물, 시뮬레이션 실행 조건·상태)를 어디서 얻는지: 응답에 담겨 오는지, 프론트 화면에서만 확인되는지 | ③ 실행 판정 자동화 여부 결정 | 미확인 |
| 4 | **화면 캡처** 방법: 규격서는 "채팅창을 제외한 프론트 화면 캡처 저장"을 요구. 프론트 주소와, 캡처를 시스템이 저장하는지 / QA 시스템이 브라우저로 찍어야 하는지 | 캡처 파일 저장 단계 구현 방식 결정 | 미확인 |
| 5 | AI7 **사례별 초기화·선행 상태 설정** 방법 (카메라 초기화, LOD 건물·기상 효과 On/Off 등)과 **시뮬레이션 실행 대기 상한**(○분) | 사례를 독립 실행하고 미실행을 판정하기 위해 필요 | 미확인 |
| 6 | AI6·7 **로그 파일명**: 규격서 AI7은 `command_parse_log_ai7.jsonl` + `sim_execution_log_ai7.jsonl` 두 파일, AI6은 미기재. 지금 QA 시스템은 `command_log_ai6.jsonl` / `command_log_ai7.jsonl` 한 파일 | 규격서 문구와 실제 파일명 맞추기 | 정해야 함 |

1~4가 확인되면 결과 파일 없이 버튼 한 번으로 실행·캡처·채점까지 이어지도록 실행기를 붙입니다.
